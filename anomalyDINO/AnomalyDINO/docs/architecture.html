Inside AnomalyDINO

AnomalyDINO (Damm et al., WACV 2025) detects defects without training a single weight. It leans entirely on a frozen DINOv2 backbone and a nearest-neighbor search over patch features — the only things that change between categories, or between few-shot and zero-shot, are which patches go into that search.

arXiv:2405.14529 backbone: DINOv2 (frozen) no training / no fine-tuning repo: anomalyDINO/AnomalyDINO

01 The core idea

Every design choice below serves one goal: turn "is this patch normal?" into a distance to the nearest normal patch ever seen.

AnomalyDINO has no classifier and no decoder. A pretrained DINOv2 vision transformer slices every image into a grid of patches and embeds each one in a 384–1536 dimensional space (depending on backbone size). Because DINOv2 was trained with self-supervised objectives across huge, diverse image corpora, patches that look structurally alike — regardless of object category — land close together in that space, and patches that don't (a scratch, a dent, a foreign object) land far from anything "normal."

Detection is then just k-nearest-neighbor search: embed a handful of known-good reference images once, store their patch vectors in a FAISS index (the "memory bank"), and for every patch of a new test image, look up its distance to the closest reference patch. A test image with a defect will have a cluster of patches that sit unusually far from anything in the memory bank.

02 The few-shot pipeline

One frozen encoder, run twice — once to build the memory bank from k reference images, once to score a test image against it.

Why "mean of the top 1%" instead of the single worst patch? Taking the max patch distance is brittle — one noisy token can flip the score. Averaging the worst 1% is an empirical tail statistic (value-at-risk at the 99th percentile): it still weights the defective region heavily, but a lone outlier patch can't dominate the whole image score.

03 What zero-shot removes

The batched zero-shot mode (run_anomalydino_batched.py) reuses the same encoder and the same top-1% aggregation — it just deletes the one component that needs curated "good" examples: the memory bank.

This is why zero-shot can occasionally beat low-shot few-shot in these results: with only 1–2 reference images, the memory bank is a thin, possibly unrepresentative sample of "normal," while the zero-shot batch draws on every test image in the category at once. It's also why zero-shot is fragile in principle — it silently assumes the test batch is mostly defect-free, an assumption few-shot never has to make.

04 The tunable pieces

Everything below is a preprocessing choice, not a learned parameter — no gradient ever touches the backbone.

Backbone Which frozen encoder embeds patches — dinov2_vits14/vitb14/vitl14/vitg14 (384–1536-d), or a plain ViT-B/L for comparison (masking unsupported there). --model_name, src/backbones.py
