VisA Dataset Structure

VisA (Visual Anomaly) is Amazon's 12-category industrial anomaly detection benchmark. On disk it looks nothing like the folder layout most anomaly-detection code expects — the train/test split lives entirely in a CSV, not in directories. This page documents the raw layout and how this project converts it for AnomalyDINO.

12 object categories 10,821 images 1.9 GB CC BY 4.0 github.com/amazon-science/spot-diff

02 The raw on-disk layout

Every category has the same flat shape: all normal images in one folder, all anomalous images and their masks in two more. There is no train/ or test/ directory anywhere — that split is defined later, in a CSV.

VisA/
├── meta.json                      # mirrors 1cls.csv as JSON, {train,test} → per-category lists
├── split_csv/
│   ├── 1cls.csv                   # standard one-class split — used by this project
│   ├── 2cls_fewshot.csv           # supervised split, small anomaly sample in train
│   └── 2cls_highshot.csv          # supervised split, larger anomaly sample in train
├── candle/
│   ├── image_anno.csv             # flat per-image label/mask listing, no split column
│   └── Data/
│       ├── Images/
│       │   ├── Normal/            # 0000.JPG … 0999.JPG (1000 files)
│       │   └── Anomaly/           # 000.JPG … 099.JPG  (100 files)
│       └── Masks/
│           └── Anomaly/           # 000.png … 099.png  (binary, one per anomaly image)
├── capsules/  (same shape)
├── cashew/    (same shape)
├── … 8 more categories, same shape
└── pipe_fryum/ (same shape)

Filenames don't reliably tell you the split either — candle/Data/Images/Normal/ mixes future train and test images together; Masks/Anomaly/ holds a binary PNG for every anomalous image, at the same resolution as its source photo, and only for anomalous images (normal images have no mask).

03 The split lives in a CSV, not a folder

Three interchangeable split files ship with VisA, all with the same object,split,label,image,mask header and the same 10,821 rows — they just draw the train/test line differently.

FileUse casecandle example (train / test-good / test-bad)
1cls.csv Standard unsupervised one-class AD benchmark — train sees only normal images; used by this project (few-shot & zero-shot). 900 / 100 / 100
2cls_fewshot.csv Supervised split — a small number of labeled anomalies also placed in train. 200+20 / 800 / 80
2cls_highshot.csv Supervised split with a larger labeled-anomaly training sample. 600+60 / 400 / 40

meta.json mirrors 1cls.csv as JSON ({"train": {...}, "test": {...}}, one list per category, each entry {img_path, mask_path, cls_name, anomaly}) — some AD frameworks read this instead of the CSV. Per-category image_anno.csv is not a split file: it just enumerates every image and its label/mask for that one category, with no train/test column.

04 Converting for AnomalyDINO

AnomalyDINO (and most MVTec-AD-style AD code) expects an actual train/ · test/ · ground_truth/ folder split. This project's scripts/convert_visa_1cls.py builds that layout by reading 1cls.csv and symlinking each file to its target — no image data is duplicated.
